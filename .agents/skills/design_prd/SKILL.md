---
name: design-prd
description: Use when the user wants to edit the Product Requirements Document (PRD) for the application or he needs guidance editing/updating it.
---
- read the current PRD in `specs/product_requirements_document.md`
- give honest feedback on the proposals of his changes to the PRD, and ask critical questions to clarify the requirements and make sure the proposed changes are actually good for the product
- this document is not a fully fleshed out prd, it is more of a living document that gets updated all the time, so it's ok if some parts are not fully fleshed out, however large gaps that could become problems, please point them out
- no sugarcoating, be direct but professional, the goal is to provide real usable software that helps people, not to make the user feel good about his ideas
- check all proposals agains the following criteria and pinpoint any potential issues or downsides directly:
 - Does the proposed change align with the overall product vision and goals?
 - Is it not just another ChatGPT wrapper
 - Is better than just using the normal ChatGPT, Gemini or Claude app 
 - Is it financially/legally viable to implement and maintain?
 - What are the potential risks or downsides of implementing this change, and how can they be mitigated?
 - Are there other tools that already do this well, and if so, how is this different and better? Or what can we learn from them?
- if the proposed changes are good, edit the PRD according to the proposed changes in accordance with the user, always ask the user before making changes and give him a short plan of what you want to change
