### 🟡 Major (Highly recommended to fix)
1. **React Component Direct Invocation and Fragile Stringification in Unit Test** - [apps/web/app/page.test.tsx:L10-L13](file:///Users/kevinsmith/Documents/development/typescript/ai-learning-support/apps/web/app/page.test.tsx#L10-L13)
   - *Problem*: In `apps/web/app/page.test.tsx`, the component is invoked directly as a function `Page()`, and its return value is serialized via `JSON.stringify` to assert contents. This is a severe anti-pattern in React testing. It will fail if hooks, contexts, or async Server Components are introduced in the future.
   - *Suggested Fix*: Use standard React rendering via `react-dom/server`'s `renderToStaticMarkup` to render the component as JSX, keeping it robust and aligned with standard React testing practices.
     ```typescript
     import { describe, expect, it, vi } from "vitest";
     import { renderToStaticMarkup } from "react-dom/server";
     import Page from "./page";

     vi.mock("@ai-learning-support/core", () => ({
         core: () => "mocked-core-greeting",
     }));

     describe("Page component", () => {
         it("should render and display the greeting from core", () => {
             const html = renderToStaticMarkup(<Page />);
             expect(html).toContain("mocked-core-greeting");
         });
     });
     ```
